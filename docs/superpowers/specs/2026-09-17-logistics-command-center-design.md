# 物流协同工作台设计

用户授权自主规划、开发和验收，最终查看可运行结果。以现有项目为事实来源；旧记忆中的主分支状态已经过期。

## 产品目标

在智营台内增加物流部门工作台，将发货承诺、实际出库、在途轨迹、预计到货、实际签收和逆向退货放在同一工作流中。员工能定位需处理的运单、领取异常任务、推进处理并核对留痕。

## 决策

采用同仓库模块化扩展，复用 Vue 3、Element Plus、FastAPI、SQLAlchemy 和现有用户/店铺授权。独立 `/app/logistics` 页面提供聚焦物流的导航，并可返回运营工作台。备选的独立微服务和另建前端项目会重复认证、数据和部署，不采用。

业务模型以物流 Shipment 为事实主线，可关联现有 Order，但不会倒写电商订单、退款金额或库存。追加事件保存轨迹与操作记录；ReturnCase 管理退货；ExceptionTask 跟踪异常；AgentRun 保存巡检结果。

## 必须可用的流程

1. 总览：运单数量、待发货、在途、已签收、时效风险、退货处理中、承运商表现与近期流转。
2. 运单：店铺/状态/承运商/关键词筛选、分页、详情、发货及到货时间、可追加轨迹、合法状态推进。
3. 退货：申请、审核/等待寄回、退回运输、仓库收货、质检、完成或拒绝；完成只代表物流闭环，不执行退款。
4. 异常：巡检生成超时未发、运输延误、长时间无轨迹、退货滞留任务；任务可分配、处理中、解决，保留说明。
5. Agent：可解释规则巡检读取真实数据库，幂等创建异常任务并生成处理建议；范围内中文问答/摘要引用运单，显示规则模式，不能冒充外部大模型或承运商实时数据。
6. 数据：演示数据相对首次启动时间生成，重启不重置；可手工新建运单与录入节点。支持导出可见数据。

## 约束

- 所有 API 复用服务端用户与店铺鉴权，不能仅依赖界面隐藏。
- UTC 保存和校验时间，界面统一显示北京时间；实际发货/到货不允许写入未来或逆序时间。
- 状态机拒绝非法跳转；并发写入有版本/冲突保护；巡检重复执行不产生重复任务。
- 无生产物流平台凭据，不连接真实承运商、不发送对外消息、不执行真实退款。
- 演示启动绑定 127.0.0.1，使用独立 SQLite 文件；标准部署保持现有 PostgreSQL/Alembic 工作流。
- 复用现有依赖；运行文件、日志、缓存保存在 D 盘。保留用户已有未跟踪文档。
- 前端提供加载、无数据、失败、操作反馈、键盘可访问和小屏布局。

## 视觉方向

运单优先的中文业务界面：暖白背景、深色文字、低饱和青绿语义强调、清晰数字、紧凑表格和独立详情面板。采用 minimalist-ui 的简洁层级与留白原则，沿用现有图标与组件。拒绝营销页巨型标题和装饰性数据。

## 验收

API 测试覆盖完整运单/退货流程、店铺隔离、无效时间、并发/幂等、异常关闭与再检测、受限中文查询。前端类型检查与构建通过；真实本机服务浏览器验收覆盖筛选、详情、巡检、退货及异常操作，保存桌面与手机截图。现有回归通过后交付本地入口、一键启动和操作说明。
